# Style guide
- Avoid short phrase "zingers" such as "That's the shift." or "That's the magic.". Use medium length sentences, aim for something that is easy to read but doesn't run on.
- Use brackets to separate ideas, not dashes.
	- Good: "Your other work (project A, task B) was good"
	- Bad: "Your other work — such as on project A and task B — was good"
- Use British English spell
- Don't inject enthusiasm that the original doesn't have

# Coding
- Create a local commit with a descriptive name when completing each step of a plan
- Where appropriate, add a short summary of the changes to the commit message
- The `gh` tool is not available. If asked about changes on a PR or branch, diff the current HEAD against main or master
